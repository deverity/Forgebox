# forge-net

**O que é:** Alocação de portas (`ports::PortAllocator`: faixas nomeadas do `forgebox.toml`, reservas persistidas na tabela `ports`, checagem de bind para portas excluídas pelo sistema, conflitos com processos externos via `forge_core::platform::PortTable`; implementa `forge_core::model::port::PortReservations`, que o daemon injeta nos pools de `forge-fcgi`), o resolvedor DNS das zonas locais (`dns`: hickory-server UDP+TCP em `127.0.0.1:53` com fallback `127.0.0.53:53`, ator `dns-server`, zonas `*.test` e remotas `*.hml.test`, NXDOMAIN fora delas, cliente de consulta direta e diagnóstico com dicas), a política que faz o Windows perguntar a ele (`policy::DnsPolicyManager`: regra NRPT via `forgebox-helper`, fallback no bloco gerenciado do `hosts`, flush do cache, eventos `dns.policy_applied`/`helper.op`) e, no futuro, regras de firewall.

**O que não é:** Não eleva privilégios por conta própria: toda mudança de NRPT/`hosts` passa por `forge_core::helper::HelperClient` (UAC, [ADR-0022](../../docs/adr/0022-elevated-helper-protocol.md)). Não lê registro nem chama Win32: usa os traits `DnsPolicy`, `PortTable`, `NetAdapters` de `forge-core`. Não repassa consultas a upstream. Não publica `port.conflict` (o daemon publica a partir de `PortAllocator::conflicts`). Não é dependência de `forge-supervisor`.

**Testes:** unitários com tabela TCP falsa em `src/ports.rs`, zonas e respostas em `src/dns/zones.rs`; `tests/ports_windows.rs` (sockets reais); `tests/dns_server.rs` (servidor real em porta alta: A/AAAA, NXDOMAIN, UDP/TCP, fallback de endereço, zona remota, reload, 200 clientes, pacotes inválidos); `tests/dns_policy.rs` (política em memória com `HelperClient` + `FakeElevation`, contrato dos payloads com `forge-ipc`); `tests/dns_diagnose.rs` (dicas com fontes falsas e leitura real do Windows). Teste manual: `cargo run -p forge-net --example dns_serve` ([docs/06](../../docs/06-sites-vhosts-multi-php.md) §5.5).

**Quem depende dele:** `forge-daemon`.
