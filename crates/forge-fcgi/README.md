# forge-fcgi

**O que é:** Gerenciador de pools FastCGI de PHP (`php-cgi.exe`) por versão (docs/03 §2, ADR-0003, ADR-0021): um ator `PhpPool` por versão (`PhpPool::spawn(PoolSpec, PoolDeps) -> PoolHandle`) com um worker por porta, portas via `forge_core::model::port::PortReservations` injetado, warmup FastCGI obrigatório (`FCGI_GET_VALUES` + GET de `/_forgebox/health.php`, escrito pelo pool em `etc/php/<série>/_forgebox/`), requests por worker estimadas pela tabela TCP (`PortTable::connections`, `TIME_WAIT` incluído), recycle proativo por `max_requests`/`max_rss_mb`/`max_age` (`PHP_FCGI_MAX_REQUESTS` vira teto de segurança acima disso), scaling `min`..`max` por conexões `ESTABLISHED` e `idle_timeout`, drenagem atrelada à aplicação do upstream, eventos `pool.scaled`/`pool.worker.recycled` e troca blue/green entre pools (`swap::swap`, `Switcher::switch(VersionId, VersionId)` para o motor de updates).

**Módulos:** `probe` (cliente FastCGI mínimo), `worker` (spawn via `forge-supervisor` — Job aninhado no do pool, barramento privado —, env `PHPRC`/`PHP_INI_SCAN_DIR`/`PHP_FCGI_MAX_REQUESTS`/`FORGEBOX_SITE`, `ConnTracker`), `pool` (ator, `PoolSpec`, `PoolStatus`), `upstream` (`UpstreamModel`, `UpstreamListener`), `events` (payloads com a forma de `forge_ipc::api::events`), `swap`.

**O que não é:** Não gera vhosts nem configs de servidor web (isso é `forge-render`/`forge-sites`; o pool entrega o `UpstreamModel` a um `UpstreamListener` do daemon, que re-renderiza e recarrega). Não aloca portas (recebe `PortReservations`, implementado por `forge-net`) nem conhece o motor de updates (`forge-provider`): não depende desses crates (docs/01 §3). Sem Win32 aqui.

**Testes:** unitários (protocolo FastCGI, pares nome-valor, saída CGI, health, ambiente/argumentos do worker, chave das conexões, `ConnTracker`, spec); `tests/pool_fake.rs` usa o php-cgi falso de `tests/fake_php_cgi/` (projeto cargo independente, sem deps, compilado pelo teste num target próprio) com processos, Job Objects e tabela TCP reais: start com `min`, recycle por `max_requests` sem erro, scaling para cima/para baixo, worker morto reposto, worker que sai só drena depois do listener aplicar, blue/green sob carga, troca na mesma série, troca que falha, recycle por idade e RSS, falhas de start, drop do pool, bloco upstream renderizado com os templates reais de `forge-render` (dev-dependency); `tests/pool_payload_contract.rs` desserializa os payloads em `forge_ipc` (dev-dependency). `tests/php_pool_online.rs` (`#[ignore]`, `cargo test -p forge-fcgi --test php_pool_online -- --ignored --nocapture`) baixa PHP 8.3 (`nts-vs16-x64`) e 8.4 (`nts-vs17-x64`) oficiais com SHA-256 do `releases.json` para `C:\apps_src\Forgebox-wt\cache` (ou `FORGEBOX_TEST_CACHE`), extrai uma vez em `C:\apps_src\Forgebox-wt\tmp\php-extract` (ou `FORGEBOX_TEST_TMP`) e cobre: dois pools simultâneos, scaling com 16 conexões, recycle a cada 20 requisições e blue/green 8.3 → 8.4 sob 200 requisições concorrentes. Sem servidor web aqui: os clientes FastCGI do teste fazem o papel dele, relendo o upstream a cada requisição; o e2e com nginx + `oha` é o smoke de M1.

**Quem depende dele:** somente `forge-daemon`.
