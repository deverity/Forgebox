# forge-core

**O que é:** Base do domínio: `ForgeRoot` e todos os caminhos da raiz (`paths`), IDs (`ToolId` slug + newtypes ULID, `ids`), `ForgeError` com códigos estáveis (`error`), `Event`/`EventBus` com `seq` (`event`), store SQLite com migrations, thread de escrita e pool de leitura (`store`), `forgebox.toml` (`config`), traits de plataforma (`platform`: `LinkFs`, `CaseSensitiveFs`, `CodeSign` — Authenticode —, `ProcessControl`/`ProcessGroup` — Job Objects, spawn suspenso com stdio capturado, `CTRL_BREAK` via `forgebox-ctrl`, `WM_CLOSE` —, `ProcessStats`, `PortTable` — listeners TCP com PID/exe, conexões `ESTABLISHED` por porta, `connections(portas)` com todas as conexões (inclusive `TIME_WAIT`) e sockets UDP com PID/exe (`udp_endpoints`) —, `RuntimeDeps` — VC++ Redistributable por registro + versão de arquivo —, `TrustStore`, `DnsPolicy` — regras NRPT, `hosts`, flush do cache —, `Elevation` — `forgebox-helper` via UAC —, `NetAdapters`), o protocolo do helper elevado (`helper`: allowlist `HelperOp` + validação, pedido/resposta, bloco gerenciado do `hosts`, `HelperClient`, `FakeElevation`; [ADR-0022](../../docs/adr/0022-elevated-helper-protocol.md)), sintaxe de nomes DNS (`dns_name`), reservas de porta (`model::port` + `store::PortRepo`; o trait `model::port::PortReservations` é o alocador para crates que não dependem de `forge-net`, como `forge-fcgi`), a paridade Linux de pastas (`fs::case`: status, conversão reversível de árvores para case-sensitive recriando as pastas e renomeando arquivos, `recover()` após queda, job `CaseConversions` com eventos `fs.case_sensitivity_*`; [ADR-0026](../../docs/adr/0026-case-conversion-tree-recreation-and-mismatch-finder.md)) e o esqueleto de concorrência (docs/03 §7, ADR-0011/0014): atores e supervisor (`actor`), jobs (`jobs`), travas ordenadas (`sync`) e runtime tokio (`runtime`).

**O que não é:** Não supervisiona processos (estados, cascata de parada, logs: `forge-supervisor`) e não fala com rede ou IPC; só oferece as primitivas de processo da plataforma. Chamadas Win32 ficam só em `src/platform/windows/` (junction via crate `junction`; flag case-sensitive via `NtSetInformationFile`; Authenticode via `WinVerifyTrust` em `authenticode.rs`; Job Objects/`CreateProcessW`/console/`EnumWindows` em `process.rs`, `console_ctrl.rs`, `window_close.rs`; `GetExtendedTcpTable`/`GetExtendedUdpTable` em `net_table.rs`; registro e versão de DLL em `vcredist.rs`; `ShellExecuteExW runas` em `elevation.rs`; NRPT no registro e `DnsFlushResolverCache` em `dns_policy.rs`; `GetAdaptersAddresses` em `net_adapters.rs`). Tudo que toca disco/Win32 é bloqueante: em código async, use `spawn_blocking`.

**Quem depende dele:** todos os crates de domínio (`forge-manifest`, `forge-supervisor`, `forge-fcgi`, `forge-render`, `forge-net`, `forge-tls`, `forge-ipc`, `forge-metrics`) e `forge-helper`.

**Concorrência (resumo):**
- `actor`: `ActorSupervisor::spawn(ActorSpec::new("mysql/default"), || MyActor::new())` → `ActorHandle`; tasks do próprio ator guardam `ctx.myself_weak()` (`WeakActorRef`), que não impede o ator de parar; `handle.actor_ref().ask(Msg::Status, Duration::from_millis(500))` (timeout obrigatório); `tell` nunca espera (`MailboxFull`). Pânico → reinício com backoff e `actor.restarted`; orçamento esgotado → `Failed` e `actor.failed`. A ordem de travas está no topo de `src/actor/mod.rs`.
- `jobs`: `JobRegistry::start("tool.install php@8.3", |ctx| async move { ctx.progress(…); ctx.check_cancelled()?; Ok(resultado) })` devolve o `JobId` na hora; eventos `job.*` com payload versionado (`jobs::payload`).
- `store`: `store.writer().execute(|conn| …).await` (thread `forgebox-db-writer`, lotes de até 64 ops/5 ms com `SAVEPOINT` por op) e `store.reader().query(|conn| …).await` (`spawn_blocking`, conexões `query_only`). Feche com `store.close()` em contexto bloqueante.
- `runtime`: `build_runtime(&RuntimeConfig::default())` — `max(4, núcleos)` workers, `2 × núcleos` threads de bloqueio; `spawn_blocking_timeout("o quê", prazo, || chamada_bloqueante())` para Win32/arquivo/registro a partir de código async.

**tokio-console (dev):** feature opt-in `console` + `RUSTFLAGS="--cfg tokio_unstable"`, por exemplo `RUSTFLAGS="--cfg tokio_unstable" cargo run -p forge-daemon --features forge-core/console`, e chamar `forge_core::runtime::init_console()` no início do binário; depois rodar `tokio-console` (porta 6669). O build padrão não exige `tokio_unstable`.

**Notas:** feature `specta` (ligada por `forge-ipc`, que re-exporta `RequestId`) deriva os tipos TS dos IDs; feature `schemars` (ligada por `forge-manifest`) implementa `JsonSchema` para `ToolId` (padrão do slug) nos JSON Schemas dos manifestos. Testes de integração em `tests/` usam junction e NTFS case-sensitive reais; `tests/elevation_windows.rs` roda o transporte do helper de ponta a ponta sem UAC (verbo `open`) contra `tests/fake_helper` (projeto cargo independente compilado pelo teste); `tests/case_convert.rs` converte e reverte árvores reais (arquivo/pasta em uso, cancelamento, recuperação) e tem o aceite manual `laragon_www_copy_roundtrip` (`#[ignore]`: copia projetos de `C:\laragon\www`, só leitura, para `%TEMP%`); `FORGEBOX_REQUIRE_CASE_SENSITIVE=1` transforma o "skip" em falha.
